### YesAPI 倍率怎么算

YesAPI 的“充值到账”和“模型扣费”是两步，不能只看其中一个：

```text
支付 $1 -> 到账 $6.5 平台余额
调用官方标价 $10 的模型用量：

1.0x 倍率 -> 扣 $10 余额
0.4x 倍率 -> 扣  $4 余额
0.2x 倍率 -> 扣  $2 余额

$6.5 平台余额 / 0.2x = $32.5 官方标价口径用量
$1 实付 / $32.5 可用量 = 3.08%，约为官方价格的 3%
```

因此，`0.2x` 不是“支付金额打两折”，而是调用相同官方标价口径的模型用量时，只按20%消耗平台余额。叠加支付 `$1` 到账 `$6.5` 的充值比例后，最终实际成本约为官方价格的3%。具体模型的输入、输出、缓存价格及倍率，以 YesAPI 控制台实时展示为准。

### 主要优点

- **接入简单**：已有 OpenAI-compatible 客户端通常只需要替换 `Base URL` 和 `API Key`；
- **充值到账直观**：支付 `$1`，到账 `$6.5` 平台余额；
- **企业渠道调度**：付费账户单独托管，再由网关统一调配；
- **风控期间更有韧性**：单个账户异常不等于整条用户线路立即失效；
- **适合流式任务**：GPT、Claude Code、Codex、Cursor、OpenCode 等工具不需要重新学习企业路由系统；
- **选择成本低**：不要求用户先配置组织、数据区域、Provider 优先级和 fallback 规则。

### 为了稳定做出的取舍

- 与部分大规模付费用户使用同类号源网关；
- **首字略高的原因**：付费账户先独立托管，再交给网关统一调度，比单账号直连多一层处理；换来的好处是单账号异常可以被隔离和替换，不容易拖垮整条用户线路；
- **低峰短暂闪断的原因**：高用量会持续产生服务器日志，渠道方选择在每日需求最低的时段集中清理，期间可能短暂闪断一次；主动低峰维护是为了释放日志压力，保证后续高峰继续稳定运行；
- 企业 SSO、复杂 RBAC、审计和数据驻留能力不如专门的国际企业网关完整。

这些取舍没有必要隐藏。YesAPI 选择的是“连续可用优先”，而不是只追求一次请求的最低首字时间。流式任务开始输出后，首字略高对整个任务计划的影响通常可接受；每日一次可预期的低峰维护，也比上游风控后长时间无法使用更容易处理。账户托管、风险隔离和统一调度带来的收益，通常大于少量首字等待和短暂维护窗口。

### 优点

- 模型和 Provider 覆盖最广；
- 可以按价格、性能和数据策略选择路由；
- 企业组织、预算和策略能力完整；
- 适合海外产品和多模型研究。

### 缺点

- Pay-as-you-go 充值收取 5.5% 平台费；
- 国内用户还要考虑国际支付、网络和 Provider 节点；
- 路由选项很多，只想配置一个编程接口时显得偏重；
- 实际首字和稳定性取决于具体 Provider，不是一个固定结果。

**一句话结论：** 需要最多模型时选 OpenRouter；国内用户只想快速开始时，YesAPI 更省步骤。

1. 打开 [YesAPI](https://yesapi.online/?utm_source=github&utm_medium=relay_review) 注册；
2. 充值并在控制台创建 API Key；
3. 将客户端的 API 地址替换为 `https://yesapi.online/v1`；
4. 选择控制台当前支持的模型；
5. 用自己的任务验证后再决定使用规模。
